What Hugo is

A BISG-focused royalty statement prototype

Hugo helps publishers, agents, and rights professionals create, review, import, validate, and export BISG-aligned translation-rights royalty statements.

What Hugo helps you do

  • Create structured royalty statements from scratch.
  • Import and digest publisher statements, including Ullstein-style PDFs.
  • Validate completeness against BISG-oriented fields.
  • Review calculation warnings and missing mappings.
  • Export as PDF, JSON, or CSV.

Why it exists

Hugo demonstrates how royalty reporting can become clearer, more transparent, and easier to compare by translating the BISG standard into a practical interface.

Prototype status

Hugo is a public prototype for discussion and testing. It is not a production accounting system and should not be used for confidential live royalty reporting.

Ullstein-style statements

For Ullstein/Bonnier-style statements, Hugo can split a multi-book intake by Interne VertragsNr., treating Ullstein’s internal contract number as the marker for separate statements.

What Hugo now detects

  • Separate internal contract statements
  • Book/title blocks
  • Product rows such as TB and E-Book
  • ISBNs
  • Unit values from the left quantity column
  • Financial values from Berechnung in EUR / Guthaben in EUR
  • Opening balance, current royalties, and new carried-forward balance where recognizable

Review before applying

Hugo does not silently trust imports. Always review detected fields, confidence labels, calculation inferences, and unmapped lines before applying data to the statement form.

Validation and calculation warnings

Validation checks

Hugo checks whether important BISG-oriented fields are filled and categorizes them as required, recommended, conditional, or remittance-related.

Calculation warnings

  • Royalty earnings do not match rate × basis amount.
  • Opening balance and current activity do not reconcile.
  • Sublicense totals do not match expected calculations.
  • Net remittance does not reconcile with balance and payments.

BISG field IDs

Activate Show BISG field IDs in preview to display IDs such as Con61_SalesTerr or SS92_PayDue beside relevant fields.

Human review still required

Warnings are aids, not audit opinions. Users must review legal, contractual, accounting, tax, and payment details themselves.

Demo mode and limitations

Demo mode notice

Use sample or anonymized data. Do not enter confidential royalty, tax, contract, bank, or payment information in public testing.

Browser-only storage

Data stays in the browser using localStorage in this static demo. It is not a database-backed production system.

Import limitations

Results vary depending on PDF quality and layout. Scanned PDFs, unusual publisher formats, or missing labels may require manual mapping or manual entry.

Professional judgment

Hugo supports review and standardization discussions but does not replace accounting, legal, tax, or rights-management expertise.

Prototype import: Hugo can import its own JSON/CSV exports and can heuristically digest PDF or text statements. The v0.7 importer is review-based: detected values receive confidence labels, unmapped lines remain visible, and users decide what to apply.

Custom Import Profiles

Profile Builder: Create reusable, browser-local import profiles for additional publisher statement layouts. Profiles can define split rules, field mappings, abbreviations, product aliases, and calculation hints. Hugo still shows detected values for review before applying them.
Safe design: Custom profiles are deterministic rule sets. They do not use an LLM and they do not send statement data to a server.
